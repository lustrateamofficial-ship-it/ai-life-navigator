# shim: подмены серверных модулей

Здесь лежит только то, чем `build.mjs` заменяет серверные модули при сборке приложения. Серверная логика из `backend/src` попадает в приложение без изменений, а эти файлы дают ей «телефонное» окружение.

| Файл | Что подменяет |
|---|---|
| `prisma.ts` (+ `schema.json`) | базу Prisma/Postgres: хранилище в IndexedDB с теми же вызовами (`findMany`, `create`, `update`...) |
| `express.ts` | Express: маршрутизатор без сети, запросы выполняются внутри приложения |
| `server.ts` | запуск «локального сервера»: монтирует маршруты, создаёт пользователя, вызывает `localRequest` |
| `env.ts` | серверные переменные окружения: настройки берутся из хранилища телефона |
| `providers-anthropic.ts` | вызов ИИ: отдаёт запрос общей очереди сервисов (`phone/aiRouter.ts`) |
| `router.tsx` | `react-router-dom`: маленький маршрутизатор по адресу после «#» |
| `zustand.ts` | `zustand`: упрощённое хранилище состояния |
| `node-stub.ts` | модули Node, которые на телефоне не нужны (zlib, Prisma Client) |

## Правила
- Сюда добавляется только то, что подменяет модуль, который импортирует `backend/src` или React-часть. Новая возможность телефона идёт в `mobile/phone`.
- `schema.json` собирается командой `node tools/parse-schema.mjs` из `backend/prisma/schema.prisma`. Менял схему, пересобери его.
- `build.mjs` после сборки проверяет, что заменители подключены и серверные оригиналы не попали в приложение. Если серверный файл изменился так, что подмена не сработала, сборка остановится с понятной ошибкой.
